### 问题 #001

**严重性**: Critical  
**类型**: Logic  
**模块**: Worker System  
**文件**: `worker/handlers/build_handler.py`  
**行号**: 150-180

**问题描述**:
Worker在处理长时间任务时，心跳线程可能在任务完成前被意外停止，导致消息可见性超时，任务被重复执行。

**影响范围**:
- 可能导致Agent构建任务重复执行
- 浪费计算资源
- 可能产生重复的项目文件

**代码示例**:
```python
# 当前实现
heartbeat_thread = self._start_heartbeat(receipt_handle)
try:
    result = self.handler.handle(message)
finally:
    if heartbeat_thread:
        heartbeat_thread.cancel()  # 可能在任务完成前被调用
```

**建议方案**:
1. 使用更可靠的心跳机制，确保心跳线程在任务完成前持续运行
2. 添加任务幂等性检查，避免重复执行
3. 在任务开始时记录执行标记，防止并发执行

**优先级**: P0

### 问题 #002

**严重性**: Critical  
**类型**: Logic  
**模块**: API System  
**文件**: `api/v2/services/agent_runtime_service.py`  
**行号**: 200-250

**问题描述**:
流式响应中缺少完整的错误处理，当AgentCore调用失败时，可能导致客户端无限等待。

**影响范围**:
- 客户端可能挂起
- 资源泄漏（未关闭的连接）
- 用户体验差

**代码示例**:
```python
# 缺少超时和错误处理
async for event in runtime.invoke_stream():
    yield event  # 如果stream中断，没有错误处理
```

**建议方案**:
1. 添加超时机制
2. 在stream中断时发送错误事件
3. 确保资源正确清理

**优先级**: P0
