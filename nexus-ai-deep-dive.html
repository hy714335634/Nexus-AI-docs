工作流编排核心。管理项目生命周期，支持从任意阶段开始执行、暂停/停止/恢复控制。延迟加载上下文和执行器。

⚡

StageExecutor

单阶段执行器。创建 Agent 实例、收集执行指标、记录生成文件。支持多 Agent 项目的迭代处理（agent_design、tools_developer 等阶段）。

nexus_utils/workflow/executor.py
执行流程
1. 加载阶段提示词映射
2. create_agent_from_prompt_template()
3. 格式化上下文（含前置阶段输出）
4. 调用 Agent 执行
5. 收集 StageMetrics + FileMetadata
6. 触发回调 on_stage_complete

DYNAMODB

DynamoDB 数据表设计

9 张核心表，采用单表设计思想，PK/SK 组合键 + GSI 支持多维查询

表名 PK SK GSI 用途
projects project_id — status-index, user-index 项目元数据、需求、状态、工作流类型
stages project_id stage_name — 工作流阶段状态、输出、指标
agents agent_id — status-index, name-index Agent 配置、路径、运行时信息
sessions session_id — agent-index 对话会话、用户绑定、状态
messages session_id message_id — 对话消息、角色、内容、元数据
invocations invocation_id — agent-index, session-index Agent 调用记录、Token 统计、耗时
tasks task_id — project-index, status-index 异步任务状态、SQS 消息关联
tools tool_name — type-index, category-index 工具注册、参数定义、分类
artifacts project_id artifact_id — 构建产物、S3 路径、版本

🔑 键设计原则

  • · PK 使用业务实体 ID，保证分区均匀
  • · SK 用于一对多关系（如 session → messages）
  • · GSI 支持按状态、用户、Agent 等维度查询
  • · 时间戳字段支持范围查询和排序

⚡ 访问模式

  • · 线程安全单例客户端，连接池 50
  • · 懒加载表引用，首次访问时初始化
  • · 自适应重试策略（Adaptive Retry）
  • · 批量操作支持（batch_get / batch_write）

DynamoDBClient 线程安全单例
class DynamoDBClient:
  _instance = None
  _lock = threading.Lock()

  def __new__(cls):
    with cls._lock:
      if cls._instance is None:
        cls._instance = super().__new__(cls)
    return cls._instance
