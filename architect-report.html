架构设计

系统架构、模块依赖、数据流与部署

四层架构设计

Nexus-AI 采用经典的四层架构设计，各层职责清晰，通过标准化接口进行通信。上层可以依赖下层，下层不能依赖上层。

表示层 (Presentation) — CLI 工具、Web 界面 (Next.js 14)、REST API (FastAPI)
负责用户交互和请求路由。CLI 支持项目管理、构建、部署等操作；Web 界面提供可视化管理；REST API 提供标准化 HTTP 接口。
应用层 (Application) — Agent Factory、Workflow Engine、Multi-Agent Orchestrator
核心业务逻辑层。Agent Factory 从 YAML 模板动态创建 Agent；Workflow Engine 编排多阶段工作流；Multi-Agent Orchestrator 支持 Graph 和 Swarm 两种编排模式。
服务层 (Service) — Prompt Manager、MCP Manager、Multimodal Processor、Config Manager
通用服务层。Prompt Manager 管理 YAML 提示词模板和版本；MCP Manager 管理外部工具集成；Multimodal Processor 处理多格式文件；Config Manager 提供集中配置。
基础设施层 (Infrastructure) — DynamoDB、SQS、S3、AWS Bedrock
AWS 托管服务层。DynamoDB 存储项目和 Agent 数据；SQS 分发异步任务；S3 存储文件和制品；Bedrock 提供 AI 模型推理。

🔀 两代执行架构

系统同时存在两代工作流执行架构，V2 为推荐使用版本：

V1 — 顺序编排
入口: agent_build_workflow.py
执行方式: 硬编码顺序调用
断点续传: 环境变量控制
适用: 命令行直接执行
V2 — 引擎驱动 ⭐
入口: run_workflow_v2.py
执行方式: WorkflowEngine 类驱动
断点续传: 内置 execute_from_stage()
暂停/恢复: 支持（DynamoDB 控制状态）
适用: API 驱动、Web 界面集成
